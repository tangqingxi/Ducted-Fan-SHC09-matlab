## 建议的阶段2执行顺序

1. 审阅本报告，选择候选数值基准。`main`、`change-B`、`debug-ecl-position`各自有不同用途，不能因为后者更新就默认获选。1000 s真实恢复未通过状态必须随基准保留。
2. 指定仓库外且有独立副本的证据保存位置。优先备份两批正式30份原始MAT、33份WTR、对应输入/协议/锁/执行管理记录，以及Round 1–7、新GNSS回归、17份报告和在用Viewer整包。
3. 对备份生成逐文件SHA256、字节数、相对路径、来源提交/未提交来源、恢复记录。当前Phase1目录是审计索引，不是23.63 GB数据备份。
4. 核准Results manifest、状态枚举及人工审批字段，先只登记原址，不移动数据。核实unknown身份与历史复制回执的覆盖边界。
5. 固定未来数值验证预算、阈值与失败预期。结构等价性和科学验收分开；禁止放宽真实恢复阈值来完成重构。
6. 审批后才制定可回退的小批迁移执行单；每批列源/目标/锁影响/兼容入口/验证/回退副本。此时才进入阶段3。

## 建议的最终目录

```text
AeroGNC-Sim/
├── main.m、研究兼容入口、ca_setup.m  # 先保留显式入口，再经审批调整
├── src/
│   ├── runtime/                    # 两条运行链显式区分
│   ├── control/                    # 平台控制与PPID研究控制分开
│   ├── allocation/{interface,plugins}/
│   ├── effectiveness/
│   ├── sensors/
│   ├── navigation/px4_ecl/
│   ├── drivers/
│   └── lib/
├── airframes/shc09/                # 几何、模型、标定；冻结参考路径另行保留
├── configs/                       # 通用、版本化配置
├── studies/                       # 研究协议、场景、批次入口
├── analysis/                      # 指标、科研审计与离线作图
├── tools/exporters/windtrace/      # SHC09导出适配，不依赖Viewer UI
├── apps/windtrace/                 # 固定SHA的未来Submodule
├── results/<study>/<batch_id>/     # 独立状态、原始数据、证据、交付
├── artifacts/windtrace/            # 经批准的构建/回滚包；与科学结果分开
├── docs/{interfaces,validation,agent-reports}/
├── tests/
├── third_party/
└── compat/                        # 有调用者及退出标准才保留/撤除
```

以上树为职责建议；逐文件候选以[MIGRATION_MATRIX.csv](MIGRATION_MATRIX.csv)为准。存在冻结路径、未知身份或目标冲突时，矩阵不能直接充当批量移动脚本。历史源码快照应保持原布局，不能改写旧engine或锁来适应新目录。
