## 5. 主要设计结论

### 5.1 备份

- 三者（基线 / Phase 2A 清单 / 当前文档）的身份已分离；**不覆盖** Phase 2A 清单。
- 7 份 P0 文档的基线字节可通过 Git blob 重建（4 份需 LF→CRLF 变换），**与计划 SHA256 完全一致**；不采用"用当前新文档冒充基线"。
- 目标布局 `<BACKUP_ROOT>/AeroGNC-Sim/339d7b1a/snapshot/<原相对路径>`，保持原始字节与路径层级。
- 容量：一份 5,006,551,294；一份 +25% 余量 6,258,189,118；两处 12,516,378,235；恢复 scratch ≥ 6 GiB。

### 5.2 恢复验证

- 目的地 **11,144 项全部**做完整 SHA256，不接受缓存或大小比对。
- 30 份正式 MAT、33 份 WTR、3 组预检输入/锁、GNSS 回归、17 份报告 **100% 抽查**（数量有限，不设抽样比例）。
- 两个 Viewer 整包必须**整包恢复 + 隔离启动**；r14 回滚包属首次启动验证。
- 验证基准取自 `BACKUP_PLAN`，**不用复制工具自己的日志**，避免自证。

### 5.3 登记与迁移

- 顺序：历史正式批 → change-B 正式批 → 三预检 → GNSS 回归 → Round 1–7 → 中断/续跑关系 → 旧轻量证据 → Viewer 工件 → 首批迁移。
- 先登记（只建索引）后移动；移动采用"复制 → 校验 → 更新索引 → 原址保留观察"，删除另行审批。
- **331 个文件写死绝对路径**；其中 `formal_lock.json` 用绝对路径指向 `final_precheck_20261103_r1` 的 MAT，因此该批次被明确延后（W3）。
- 首批试点：W1 = 预检批 39 项 / 55,480,098 字节；W2 = GNSS 回归 25 项 / 39,102,531 字节（跨 results + docs 合并，W1 通过后才启动）。
